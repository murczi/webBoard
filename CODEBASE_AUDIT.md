Codebase audit — 12 October 2026

**Historical baseline:** these findings and the 270-file inventory describe commit `4d7b3a6`, before implementation. All 35 planned task IDs have subsequently been addressed in separate commits. Final container verification found an additional UI image runtime dependency defect, fixed separately as F15. See [the implementation and verification record](AUDIT_IMPLEMENTATION.md) for the resulting behavior and test coverage. Source links below deliberately point to the baseline commit.

The application already uses object-oriented architecture: dependency injection, service/repository interfaces, concrete adapters, and polymorphic health handlers. Its domain models mostly hold data, however, and several business rules are repeated across layers. More encapsulation and composition would help; a wholesale rewrite or inheritance hierarchy for every model would not.

This review inventoried all 270 files tracked at the start of the audit. First-party source, interfaces, models, Razor views, JavaScript, styles, tests, migrations, project configuration, deployment scripts, workflows, and documentation were reviewed. Generated migration models were checked in conjunction with migrations and model-consistency tests. The 60 vendored library files were inventoried as third-party assets, not independently audited line by line or certified free of vulnerabilities. Build output and private environment/credential files are outside the review. The per-file inventory follows the findings. No application code was changed.

Validation: all 159 .NET tests passed, including the 20 PostgreSQL tests initially skipped without a connection string; all 6 JavaScript tests and 57 installer tests passed. PostgreSQL ran in an isolated disposable container. Installer tests mock lifecycle and privileged operations; they do not establish that every real deployment works. Additional probes reproduced the behaviors specifically labeled below. No full browser end-to-end test, live systemd-control test, or production-load benchmark was run.

**Logic and behavior findings**

1. **F01 — High: deletion and revocation have inconsistent enforcement.** [JWT setup](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Web/Program.cs#L100), [host mutations](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Domain/Services/HostManagementService.cs#L31), [module mutations](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Domain/Services/ModuleManagementService.cs#L31), [current user checks](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Domain/Services/UserCrudAccessService.cs#L113), [operation checks](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Infrastructure/Repositories/ModuleOperations.cs#L17).
   JWT validation checks the token but does not recheck whether the user still exists or is deleted. Host/module CRUD and reads authorize using the old token claims, whereas permission writes and module operations recheck current database grants. A live HTTP probe deleted the signed-in account and still received HTTP 200 from `/ModuleManagement` using its existing JWT. Host/module mutation handlers likewise have no current-account/current-grant check. The default token lifetimes are eight hours or thirty days with Remember me. Define one revocation policy, validate account/session validity centrally, and apply current-grant checks consistently to protected mutations. Refresh access being optional is inadequate for account deletion.

2. **F02 — High: documented proxy deployments produce session cookies without Secure.** [pipeline](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Web/Program.cs#L152), [login](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Web/Pages/Login.cshtml.cs#L41), [registration](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Web/Pages/Register.cshtml.cs#L43), [cookie options](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Web/Authentication/JwtSessionService.cs#L103), [proxy generation](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/deploy/install.sh#L872).
   Caddy terminates HTTPS and forwards HTTP to the app. Startup does not configure forwarded headers, and login/registration/access refresh explicitly pass `Request.IsHttps` to cookie creation. An HTTP request carrying `X-Forwarded-Proto: https` successfully registered and received a session cookie whose Secure flag was false. This contradicts the deployment guides' unconditional Secure-cookie claims; HTTPS redirection/HSTS also lack the original request scheme. Configure forwarded headers with an explicit trusted-proxy boundary before middleware that reads the scheme, and enforce Secure cookies in production. [Microsoft's ASP.NET Core proxy documentation](https://learn.microsoft.com/en-us/aspnet/core/host-and-deploy/proxy-load-balancer?view=aspnetcore-10.0) describes restoring the original scheme when HTTPS is proxied over HTTP.

3. **F03 — High under overlapping interactions: permissions can be displayed for the wrong save target.** [permission editor](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Web/Pages/UserManagement.cshtml#L258).
   Each click sets the shared hidden user ID and launches a fetch. There is no cancellation or request-generation check before rendering its response. Open A, then open B while A's request is pending: if B responds first and A responds last, the editor displays A's permissions while submitting changes to B. A JavaScript probe executing the actual click-handler logic reproduced `target B; displayed A permissions`. Bind responses to a request and target ID and discard stale completions. The host Test agent UI has a similar smaller problem: a result can be displayed after the entered URL or modal target changes.

4. **F04 — High for historical upgrades: the foreign-key fix fails on a populated initial schema.** [migration](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Infrastructure.Configuration/Migrations/20260820144601_FixModuleTypeForeignKey.cs#L27).
   The migration creates required `ModuleTypeId` with default 0, then references `ModuleTypes.Id`; the initial seed contains ID 1, not 0. Existing module rows are never backfilled. Migrating an initial-schema database containing a valid module reproduced SQLSTATE 23503 on `FK_Modules_ModuleTypes_ModuleTypeId`. Fresh installs pass because the old table is empty. Historical data also needs review in [UpdateConfigurationModel](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Infrastructure.Configuration/Migrations/20260820154924_UpdateConfigurationModel.cs#L175), which adds a required actor FK against a newly created Users table without mapping old audit actors. Establish populated-predecessor upgrade fixtures and a repair path for affected deployments; do not casually rewrite migration history already deployed.

5. **F05 — Medium: Steam rollback differs from the other module-type rollbacks and fails.** [Steam Down](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Infrastructure.Configuration/Migrations/20260929103542_AddSteamModules.cs#L48), [Minecraft Down](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Infrastructure.Configuration/Migrations/20260826164258_AddMinecraftModules.cs#L43).
   Docker, Systemd, and Minecraft migrations reassign dependent modules to Http before deleting the module-type seed. Steam deletes type 5 without handling dependent rows. Downgrading a database with a Steam module reproduced SQLSTATE 23001 on the module-type FK. Choose a consistent, explicit downgrade policy, with preservation/export or reassignment of dependent configuration as appropriate.

6. **F06 — Medium: an unreachable host cannot be disabled or renamed.** [host update](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Domain/Services/HostManagementService.cs#L41).
   Every host update requires a healthy agent, including `IsEnabled=false` and name-only edits. A probe attempting to disable a host with a failing health check was rejected before the repository update. This prevents the ordinary configuration action needed during an outage. Scope health validation to changes that need it, such as enabling or replacing the agent endpoint, and permit administrative disabling during an outage.

7. **F07 — Medium: Minecraft port requirements disagree between UI, domain, and health checks.** [domain validation](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Domain/Services/ModuleManagementService.cs#L121), [browser requirement](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Web/wwwroot/js/module-editor.js#L46), [health handler](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Web/Services/ModuleHealthHandlers.cs#L57).
   The nullable range pattern rejects out-of-range values but permits null. Browser JavaScript requires the port, while the domain successfully saves a Minecraft module with no port and the health handler subsequently reports NotConfigured. Steam explicitly rejects null. This was reproduced through the domain service. Require a port or apply a documented default consistently. Minecraft address validation also only excludes whitespace/slashes, whereas Steam additionally validates hostname syntax; use a common endpoint policy where applicable.

8. **F08 — Medium: systemd names use incompatible validators.** [domain](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Domain/Services/ModuleManagementService.cs#L136), [status client](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/WebBoard.Agent/SystemdClient.cs#L141), [operation validator](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/WebBoard.Agent/Operations.cs#L83), [installer validator](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/deploy/install.sh#L110).
   Domain validation accepts a case-insensitive `.service` suffix and any allowed leading character. Agent status validation requires lowercase `.service`; operations/installer additionally require a leading letter, digit, or underscore. A module named `-bad.SERVICE` was accepted by the domain and rejected by the agent status validator. Even `-bad.service` passes the domain/status predicate but cannot be operated on. Agree on one service-name contract, test it across all boundaries, and use explicit argument separation for status queries too.

9. **F09 — Medium: URL validation checks the length before normalization.** [URL normalization](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Domain/Services/ModuleManagementService.cs#L148), [database limits](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Infrastructure.Configuration/Configurations/ModuleConfiguration.cs#L42).
   The service checks the input against 2048 characters and then returns `uri.AbsoluteUri`. Percent encoding can expand the result past the database limit. A short URL containing 1000 `é` characters was accepted and normalized to 6021 characters. Persisting it would fail the database column limit instead of reporting a validation error. Validate the normalized representation that will actually be stored, for both health and management URLs.

10. **F10 — Medium, concurrency risk: host-name uniqueness means different things in the service and database.** [name query](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Infrastructure/Repositories/HostRepository.cs#L24), [unique index](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Infrastructure.Configuration/Configurations/HostConfiguration.cs#L21).
    The service treats host names as case-insensitively unique, but the database's ordinary text index enforces exact-name uniqueness. Concurrent creates named `Server` and `server` can both pass the precheck and both persist. Concurrent identical names instead raise an uncaught database exception. This is a source-confirmed race risk, not a load-tested race. Enforce the chosen canonical uniqueness rule in the database and translate constraint conflicts to validation results. Also standardize culture-sensitive `.ToLower()` handling in host/user lookups.

11. **F11 — Medium: operation outcomes lose typed failure information across transport, audit, and replay.** [agent response handling](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Web/Services/AgentOperationsClient.cs#L10), [audit classification/replay](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Infrastructure/Repositories/ModuleOperations.cs#L69), [agent errors](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/WebBoard.Agent/Program.cs#L146).
    The agent can return structured timeout JSON with HTTP 504, but the UI client discards bodies for non-success status codes. A probe confirmed that a 504 with `TimedOut=true` becomes `TimedOut=false`. Audit classification then infers Unknown from whether English message text contains `unknown`; the fallback `verify target state` message is recorded as Failed. A communications failure after dispatch may therefore appear as a definite failure. Replay also reconstructs a result without its original TimedOut flag. Use a typed operation outcome consistently and preserve uncertainty, timeout, and partial-completion information independently of message wording.

12. **F12 — Medium: disabled/deleted host state is missing from module presentation and capability checks.** [module projection](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Infrastructure/Repositories/ModuleRepository.cs#L18), [capability checks](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Infrastructure/Repositories/ModuleOperations.cs#L11), [collector eligibility](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Infrastructure/Repositories/MonitoringCollector.cs#L13), [latest results](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Infrastructure/Repositories/MonitoringReader.cs#L16).
    Collection and execution check that the host is enabled and not deleted. The projected ModuleModel includes the host URL/name but not that state, and capability discovery only checks the module and URL. An enabled module whose host is disabled/deleted can still query that agent and offer operations that execution will reject. After invalidation, its dashboard message says Awaiting monitoring data although the collector deliberately skips it. Discovery dropdowns also list disabled hosts while their lookup endpoints reject them. Carry effective eligibility and its reason into read models and use the same rule for collection, choices, controls, and messages.

13. **F13 — Low: retained-history explanations disagree between endpoints.** [block lookup](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Infrastructure/Repositories/MonitoringReader.cs#L37), [history slices](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Infrastructure/Repositories/MonitoringReader.cs#L70).
    Block lookup labels old times Outside retained history. HistoryAsync uses that label only when the entire requested range precedes the cutoff; a range crossing the cutoff fills its old portion with No monitoring data. A crossing-range probe reproduced the latter. Both are Unknown, so this is a meaning/feedback discrepancy rather than a false health observation. Split the retained and unretained portions explicitly and share the labeling rule.

14. **F14 — Medium for malformed agent responses: discovery errors are less robust than health errors.** [Docker discovery](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Web/Services/DockerAgentClient.cs#L19), [systemd discovery](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Web/Services/SystemdAgentClient.cs#L32), [page handlers](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Web/Pages/ModuleManagement.cshtml.cs#L150).
    Health clients catch malformed/unsupported payload errors and return an explicit Invalid agent response. Discovery clients can throw JsonException, while the page handlers only translate HTTP and timeout exceptions. An HTTP-success response containing bad JSON therefore produces a server error instead of the structured discovery error consumed by the editor. This is confirmed from the exception paths, not a live malformed-agent integration probe. Apply a common bounded response/parser/error policy to discovery and health adapters.

**Performance findings**

- **P01 — Medium, structural risk: page rendering performs sequential live capability requests.** [operations partial](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Web/Pages/Shared/_ModuleOperations.cshtml#L7), [capability timeout](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Web/Services/AgentOperationsClient.cs#L22). Every eligible tile awaits the agent during Razor rendering, including arrangement preview. Slow agents can add roughly five seconds per tile, serially; Docker capability discovery also inspects the container. Preload capabilities with bounded concurrency, consider a short cache, or load them when an operation menu is opened. No production-load timing was measured.
- **P02 — Medium, structural risk: hovering history recomputes the whole retained timeline.** [SQL source](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Infrastructure/Repositories/MonitoringReader.cs#L40), [hover requests](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Web/wwwroot/js/monitoring-history.js#L77). BlockAsync runs window/grouping operations over all retained samples for the module before selecting the block at the requested time. At the defaults, thirty days of thirty-second samples is about 86,400 observations per continuously monitored module. Hovering can issue a lookup after each 250 ms pause. Investigate bounded neighboring-observation queries, a block projection, or caching; measure actual plans/latency before deciding. The SQL structure is confirmed; production performance impact is unmeasured.
- **P03 — Medium, measured local overhead: constructing a scoped session service computes an expensive dummy hash.** [hash initializer](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Web/Authentication/JwtSessionService.cs#L21), [scoped registration](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Web/Program.cs#L58), [dashboard injection](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Web/Pages/Index.cshtml.cs#L16). Every construction hashes a dummy password, even for dashboard/status handlers that never authenticate a password. Ten constructions took 343 ms in the audit probe, approximately 34 ms each on this machine; this is not a universal latency estimate. Initialize the dummy hash once without making the repository-dependent service a singleton.

**Standardization and object-oriented opportunities**

- **S01 — Module configuration owns too few invariants.** [ModuleModel](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Domain.Model/Modules/ModuleModel.cs#L3) has a TypeId/TypeName and every type's nullable configuration fields. [ModuleManagementService](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Domain/Services/ModuleManagementService.cs#L64) uses a long type switch and clears unrelated fields; the browser has another [definition table](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Web/wwwroot/js/module-editor.js#L8). Compose the module with typed Http/Docker/Systemd/Minecraft/Steam configuration objects, or introduce type-specific configuration validators/normalizers through a registry. Keep EF's flat schema and browser transport DTOs if useful; they need not become the domain object. The existing health-handler registry is a good pattern to extend.
- **S02 — Permission metadata is repeated.** Resource names/read-only status/read implication appear in [UserCrudAccessService](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Domain/Services/UserCrudAccessService.cs#L9), [registration](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Infrastructure/Repositories/UserAuthenticationRepository.cs#L77), SQL constraints, JWT claim construction, retry logic, and frontend labels. JWT read implication omits CanOperate although the service treats it as implying Read. Service-normalized persisted grants currently mask that difference. Use one resource/action definition and one implication rule, with explicit database compatibility.
- **S03 — Agent URL composition/security validation is repeated.** Host normalization, health endpoint creation, Docker/systemd endpoint helpers, profile matching, and operations string concatenation have different validation strictness. An AgentEndpoint value object/shared builder could own canonicalization and relative endpoint construction; authentication/network adapters can enforce their separate transport policies.
- **S04 — Time and configuration revisions have different representations.** Modules/monitoring use DateTimeOffset; hosts/users/audits use UTC DateTime; host/user/module update metadata is inconsistent. Views sometimes convert using the server's timezone while history uses the browser's timezone. Standardize a UTC storage/transport convention and explicit presentation timezone. Inject TimeProvider into time-sensitive services. Consider an explicit monitoring configuration version rather than using DateUpdated as a revision for every edit.
- **S05 — Module mapping is duplicated.** [ModuleRepository](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Infrastructure/Repositories/ModuleRepository.cs#L13), [MonitoringCollector](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Infrastructure/Repositories/MonitoringCollector.cs#L29), page input mapping, and browser data attributes each enumerate fields manually. Centralize server projections/mappings where practical and test meaningful field preservation when a type is added; do not force EF entities directly into pages.
- **S06 — Layer boundaries differ by feature.** Host/module business validation is in Domain services, but operation permission/type/outcome orchestration sits in Infrastructure/Repositories/ModuleOperations. UserCrudAccessService also tells its repository how to stage individual access-row mutations and audit entries. A domain/application operation service plus dedicated persistence/locking abstractions would make ownership consistent without hiding PostgreSQL-specific locking inside generic abstractions.
- **S07 — Process execution has two implementations.** Systemd controls use injected IProcessRunner with bounded output/environment/process-group handling. Monitoring/discovery uses a separate static subprocess runner with unbounded output and different cancellation/environment behavior. Share a runner abstraction with appropriate read-only query and control policies. AgentOperations manually creates SystemdClient despite startup registering it; inject that dependency consistently.
- **S08 — Permissions are presented incompletely.** [read-only Users view](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Web/Pages/Users.cshtml#L21) displays CRUD columns but omits CanOperate, which the management editor includes. Its resource label map also omits MonitoringHistory and falls back to the raw key. Use a shared presentation definition so users can inspect all supported grants.
- **S09 — Existing JavaScript/installer checks are outside CI.** [.github/workflows/ci.yml](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/.github/workflows/ci.yml#L32) runs .NET checks and Docker builds but never invokes the six JavaScript tests or the 57 installer tests. Add suitable Node/Python/Compose/OpenSSL checks. Installer tests have host-dependent skips, and JavaScript tests use a small DOM substitute; add browser coverage for dangerous asynchronous interactions such as F03.
- **S10 — Error handling and diagnostic detail differ.** Host validation uses exceptions and mandatory health checks; CRUD returns bool for missing records; operations use exceptions plus result records; some transport paths catch detailed errors and others surface a generic 500. Host pages collapse validation errors into name/URL feedback even for an invalid audit comment. Monitoring logs often retain only exception type, losing cause/stack context. Standardize error ownership, user messages, structured outcomes, and private diagnostic logging.
- **S11 — Edit concurrency has no explicit policy.** Module/host forms and permission replacements have no submitted version or optimistic concurrency check. A stale form can silently overwrite a newer edit; permission saving can replace grants another administrator just changed. Decide whether last writer wins is intended. If it is not, introduce a version check and a clear conflict response. This is a source-confirmed design risk, not a simulated concurrent-write failure.
- **S12 — Every metadata edit invalidates monitoring.** ModuleRepository and HostRepository invalidate current health after every update, including name/description/management-link changes. This creates Unknown/awaiting periods and historical boundaries for changes that do not affect a health check. Compare monitoring-relevant configuration before advancing its revision and invalidating results.
- **S13 — Environment-file precedence differs by entry point.** [web startup](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Web/Program.cs#L13) uses Env.NoClobber(), while [design-time database factory](https://github.com/murczi/webBoard/blob/4d7b3a6470c664e7b061198b4831f3ebe1b73bc0/src/Webboard.Infrastructure.Configuration/WebboardDbContextFactory.cs#L12) loads without it. Make precedence intentional and consistent so migrations and application startup use the same connection source.
- **S14 — Styles and error copy retain old template behavior.** site.css and workspace.css override overlapping rules for body, cards, tables, module tiles, and colors. The unreferenced scoped `_Layout.cshtml.css` still contains old navbar/footer styling; monitoring CSS retains history-block selectors although history now draws canvas rows. The production Error page recommends changing environment settings and exposes implementation guidance to end users. Consolidate theme/component tokens, remove obsolete styling after checking references, and use product-facing failure copy.
- **S15 — Some browser endpoints bypass URL generation.** Dashboard refresh hardcodes `/?handler=Status`, history hardcodes `/MonitoringHistory`, and authentication challenge hardcodes `/Login`; editor/host/permissions requests use generated Razor URLs. Standardize generated base-aware URLs if deployment beneath a path prefix is supported. Root deployment currently avoids this limitation.
- **S16 — Type extension behavior is inconsistent.** Unknown persisted module types fall through to HTTP-style configuration validation but receive Unsupported module type from the health registry. Known seeded types avoid this today. A shared supported-type registry should either reject unregistered types or define their validation/health/control capabilities. Comparison semantics also differ: domain/health dispatch ignores case, operation dispatch uses exact strings.
- **S17 — Transport contract ownership is duplicated.** Agent and domain separately declare operation request/result records; Docker/systemd DTOs are also duplicated or privately reduced. Establish an explicit versioned wire contract or shared contract package when maintaining compatible UI/agent releases. Keep API compatibility and domain behavior separate.
- **S18 — Small conventions obscure the meaningful differences.** Standardize WebBoard/Webboard naming, sealed classes where extension is not intended, formatting, named-argument style, cancellation-token naming/defaults, constructor ownership, and cohesive file placement (IModuleHealthHandler currently lives in ISteamQueryClient.cs). Agent token minimums use UTF-8 bytes, while UI profile minimums use string length. Enum numeric values are persisted and also hardcoded in SQL/JavaScript; give them explicit stable values and centralize serialization assumptions. These are maintainability issues, not reasons to add inheritance.

**Object-oriented assessment and order of work**

The service/adaptor layer is substantially object oriented already. It separates persistence, network clients, health handlers, and page presentation through interfaces and dependency injection. Health-handler composition and the JavaScript ModuleEditor/RemoteModuleOptions/SearchableSelect classes are useful existing examples. Static access helpers and pure MonitoringTimeline functions are reasonable; turning them into mutable objects would not inherently improve them.

The weaker area is invariant ownership: mutable domain DTOs permit invalid combinations, validation knows about every module type, and cross-layer permission/endpoint/outcome rules can diverge. Favor composition, narrow policy objects, typed outcomes, immutable validated configuration, and an explicit application-service boundary. A large generic repository, a common base class for unrelated services, or deep module inheritance would add indirection without directly fixing the findings.

Recommended sequence: fix F01–F03 and determine whether F04 affects any historical installations; correct validation and operation outcome contracts; unify effective host/module eligibility; then refactor module/permission/endpoint policies and mappings. Address measured or demonstrated performance concerns alongside regression coverage. Finish with naming, styling, and documentation cleanup.
